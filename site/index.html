Rogue: commands, jobs and messages. No reflection, no license fee.

A source-generated mediator, background jobs and a message bus for .NET. One Roslyn generator writes the dispatch and the serialization at compile time, so there is no assembly scan and no runtime reflection, it runs under Native AOT, and it meets or beats MediatR, Hangfire and FluentValidation in every benchmark we measure.

One generator, three jobs

Mediator, background jobs and a message bus

The same handlers serve all three. A command you Send today can run as a background job with [Job], or arrive from another service with [Message], through the same pipeline and behaviors.

Mediator

CQRS without the reflection

Queries, commands, events and streams, with open generic behaviors ordered by [BehaviorOrder]. Moving from MediatR takes one line and a compat shim.

var user = await sender
    .Send(new GetUser(id));
Jobs

Background jobs on your commands

Retries with backoff, dead-lettering, delayed, recurring (cron) and unique jobs. Durable stores on PostgreSQL and SQL Server let you enqueue inside your own transaction.

[Job, Recurring("0 3 * * *")]
record Nightly() : ICommand;
await jobs.Enqueue(
    new ShipOrder(id));
Messaging

A message bus between services

Messages travel under stable names, not .NET type names, over RabbitMQ. The outbox sends only once your transaction commits, and the inbox runs a duplicate delivery once.

[Message("orders.placed")]
record OrderPlaced(int Id)
    : IEvent;
await bus.Publish(
    new OrderPlaced(id));
Install

Start with one package and add the others when you need them

$ dotnet add package SkathIO.Rogue
$ dotnet add package SkathIO.Rogue.Jobs.Postgres
$ dotnet add package SkathIO.Rogue.Messaging.RabbitMQ
$ dotnet add package SkathIO.Rogue.Messaging.Outbox
// Program.cs
builder.Services.AddRogue();
builder.Services.AddRogueJobs();
builder.Services.AddRogueJobWorker();
builder.Services.AddRogueMessaging(o =>
    o.SerializerContext = AppJson.Default);

Library authors who only need the interfaces can take SkathIO.Rogue.Abstractions. The full list of packages is below.

Quick start

Define a request, handle it, send it

public record GetUserQuery(int Id) : IQuery<User>;

public class GetUserQueryHandler
    : IQueryHandler<GetUserQuery, User>
{
    public ValueTask<User> Handle(
        GetUserQuery q, CancellationToken ct)
        => ValueTask.FromResult(new User(q.Id, "Alice"));
}
// inject ISender / IPublisher
public class OrderController(ISender sender)
{
    public async Task<User> Get(int id)
        => await sender.Send(new GetUserQuery(id));
}

// the generator found the handler at
// compile time: no scan, no reflection

Run it in the background, in your own transaction

[Job(MaxAttempts = 3, BackoffSeconds = 30)]
public sealed record ShipOrder(int OrderId) : ICommand;

// commits or rolls back with your data
await postgresJobs.Enqueue(
    new ShipOrder(orderId), transaction, ct);
[Message("orders.placed")]
public sealed record OrderPlaced(
    int OrderId, decimal Total) : IEvent;

// sent only if the transaction commits
await outbox.Publish(
    new OrderPlaced(id, total), transaction, ct);
Benchmarks

Ahead or level in every head-to-head we measure

There is no measured head-to-head scenario where MediatR beats Rogue, on time or on allocation. If a change ever makes Rogue lose one, the loss is published in the same plain terms.

Packages

Twelve packages, one generator

SkathIO.RogueThe mediator: source generator, DI wiring and dispatcher. Send, Publish and CreateStream on a ValueTask pipeline.
SkathIO.Rogue.AbstractionsContracts only, for library authors who define requests and handlers.
SkathIO.Rogue.MediatRA MediatR compatibility shim, so a migration is one line, not a rewrite.
SkathIO.Rogue.JobsMark a command [Job] and enqueue it. A worker runs its handler with retries, backoff, dead-lettering, delays, cron schedules and unique keys.
SkathIO.Rogue.Jobs.PostgresDurable jobs: enqueue in your transaction, bulk insert with binary COPY, claim batches with SKIP LOCKED, wake workers with LISTEN/NOTIFY.
SkathIO.Rogue.Jobs.SqlServerDurable jobs: bulk insert through a table-valued parameter, batched READPAST claims and adaptive polling.
SkathIO.Rogue.MessagingA message bus: [Message] events and commands travel under stable names and reach your Rogue handlers, with retries and dead-lettering.
SkathIO.Rogue.Messaging.RabbitMQRabbitMQ transport: a topic exchange, a queue per service, publisher confirms, recovery, and JSON from other systems mapped by routing key or header.
SkathIO.Rogue.Messaging.OutboxPublish inside your database transaction: nothing is sent if it rolls back, and a message delivered twice runs its handlers once.
SkathIO.Rogue.ValidationSource-generated [Validate] rules, a rules hook and async rules from DI. 0 B on a valid request.
SkathIO.Rogue.Validation.FluentValidationA validation behavior for your existing FluentValidation validators, found automatically.
SkathIO.Rogue.LoggingA structured logging behavior for requests and responses.

Every runtime package targets .NET 8 and .NET 10. Two samples, one with jobs and messaging, are published with Native AOT and run in CI on every pull request.
